# AWS SAA-C03 Prep Suite

A study website for the **AWS Certified Solutions Architect - Associate (SAA-C03)** exam, built with **React 19** and **Vite**. It contains the exam syllabus, a 30-day plan, **93 service-by-service study pages** (each with a flow diagram you can download as a draw.io file), a practice-question bank, and a progress tracker with live totals and completion percentages. The site is fully static and designed to be deployed to **AWS S3 + CloudFront**.

Sections: Home · Syllabus · Services (catalog + 93 study pages) · Practice · Tracker

> **Authenticity statement.** Exam facts (format, scoring, price, domains, task statements) were checked against AWS's own pages and every fact links to its source. Every service page ends with a *Sources* list of AWS documentation links (all 445 URLs were checked with `npm run check:links`). Priority tiers and study-hour estimates are an **editorial judgement** (AWS does not publish per-service question counts) and are labelled that way in the UI. There are **no real exam questions** in this project: they are protected by AWS's candidate agreement. Questions are either **official** (the 10 sample questions AWS publishes, with AWS's own explanations) or **mock** (original, written for this site and not peer reviewed).

## Tech Stack

| Concern              | Choice                                            |
| --------------------- | -------------------------------------------------- |
| UI library            | [React 19](https://react.dev/)                     |
| Build tool / bundler  | [Vite](https://vite.dev/)                           |
| Routing               | [react-router-dom 7](https://reactrouter.com/) using `HashRouter` (works on any static host with no rewrite rules) |
| Animations            | [Framer Motion](https://motion.dev/)                |
| Icons                 | [react-icons](https://react-icons.github.io/react-icons/) |
| Styling               | Plain CSS with CSS custom properties (AWS-style light and dark themes), component-scoped stylesheets |
| Language              | JavaScript (JSX) with JSDoc annotations             |
| Linting               | [oxlint](https://oxc.rs/)                           |

No backend, database or server-side rendering: the app builds to static HTML/CSS/JS. Your tracker data and quiz history live in the browser's `localStorage`.

**Design principles**

- **Data/presentation separation** - every fact lives in `src/data/`; components render it. Adding a service never needs JSX changes.
- **Single source of truth** - `serviceCatalog.js` drives the Services page, the tracker, the study plan and the validation script.
- **One component per file** with its own CSS file, **JSDoc** on every component, hook and exported function, and **CSS custom properties** for colours, spacing and motion.

## Building for Production

```bash
npm run build
```

Output goes to `dist/` with content-hashed filenames (each service's content is a separate lazy chunk). Because the app uses `HashRouter` and a relative `base`, `dist/` works from any folder or bucket path, and deep links look like `https://your-domain/#/services/vpc`.

## Deploying to AWS S3 + CloudFront

```bash
npm run build
aws s3 mb s3://your-prep-site-bucket                         # first time only; keep it private
aws s3 sync dist/ s3://your-prep-site-bucket --delete
aws cloudfront create-invalidation --distribution-id YOUR_DISTRIBUTION_ID --paths "/*"
```

- Create a CloudFront distribution with the bucket as origin using **Origin Access Control (OAC)**, and set `index.html` as the default root object.
- Unlike a history-router SPA, **no 403/404-to-index.html error rule is needed**, because routes live after the `#`.
- Attach an ACM certificate (in `us-east-1`) if you use a custom domain.

## Adding or Editing Study Content

1. Add (or edit) the entry in `src/data/serviceCatalog.js` (`id`, `name`, `category`, `tier`, `hours`, `domains`, `summary`), and put the id into a day of `src/data/studyPlanData.js`.
2. Create `src/data/services/<id>.js` - copy an existing file such as `s3.js` (full) or `ecr.js` (compact) as a template.
3. Run `npm run validate`, then `npm run dev` to look at the page.

Content schema:

```js
export default {
  tagline,                         // one line
  notice?: { title, text },        // optional warning shown above the introduction
  intro: [],                       // 5-6 bullet points (4+ for low-priority services)
  useCases: [{ title, detail }],
  importance: { points: [] },
  cli: [{ command, description }],
  sdk: { summary, snippets: [{ title, language, code }] },
  examples: [{ title, scenario, steps: [], code? }],
  diagram: { title, nodes, edges, groups?, steps },      // see the next section
  questionTypes: [{ pattern, hint }],
  questions: [{ source: 'official' | 'mock', reference?, domain, multi?, stem, options, answer: ['A'], explanation }],
  keyFacts: [], traps: [{ clue, answer }], related: [], sources: [{ title, url }],
};
```

Rules the validator enforces: minimum counts per priority tier, every question has a domain, 4-5 options and an explanation, `multi: true` (and 5+ options) whenever more than one answer is correct, related ids exist in the catalog, and every source is an `https://` URL.

Authoring tips:

- Write only what you can source. Put the AWS documentation page in `sources`; do not copy numbers from memory when AWS limits change often.
- Use `"double quotes"` for strings that contain an apostrophe.
- Keep mock questions to **one defensible answer** and vary the position of the correct option.

## Flow Diagrams and draw.io Export

Each service has a small diagram spec instead of a drawing:

```js
diagram: {
  title: 'Request path',
  nodes: [['user', 'Users', 'actor', 0, 1], ['alb', 'Application Load Balancer', 'network', 1, 1]],   // [id, label, kind, column, row]
  edges: [['user', 'alb', 'HTTPS']],                                                                  // [from, to, label?, 'dashed'?]
  steps: ['Users connect to the load balancer.'],
}
```

The same spec is rendered as SVG on the page and exported as a **draw.io (`.drawio`) file** (button on every diagram; `npm run diagrams` also writes one file per service into `public/diagrams/`, which is git-ignored and rebuilt on every build). Open them in [app.diagrams.net](https://app.diagrams.net/) or the draw.io desktop app and edit freely.

Layout rules checked automatically by `npm run validate`: at most 4 columns and 3 rows; edge labels up to 32 characters; one labelled edge per side of a node; an edge may not pass through another node.

## Code Conventions

- **JSDoc** on every component, hook and exported function.
- **One component per file**, colocated with its own CSS file.
- **Data/UI separation**: JSX files contain no study content.
- **CSS custom properties** for every colour, spacing and motion value (light default, dark via `data-theme`).
- Print styles are included: use **Print / Save as PDF** on the Syllabus or any service page.

## Known Limitations

- The official exam guide has changed since the 2023 PDF that most study material still copies; this site follows the current in-scope list (see the banner on the Syllabus page). Re-check the guide the day you book the exam.
- AWS Snow Family stays in the exam scope even though Snowcone is discontinued and Snowball Edge is closed to new customers; the Snow Family page explains this.
- Mock questions are original and have not been peer reviewed.
- The INR price is the figure on AWS's pricing page; whether tax is added at checkout is not stated there.

## Troubleshooting

- **Blank page after `npm run dev`** - check `node -v` (20+) and re-run `npm install`.
- **`npm run build` fails in `prebuild`** - read the first lines of the validation output; each problem names the file and the rule.
- **A diagram fails validation** - move one of the nodes so the second labelled edge becomes a straight vertical line (see the layout rules above).
- **Scroll animations not replaying** - they fire once per visit; refresh the page.
